# FSDP 要点与面试题

<div class="notebook-hero" markdown>

<span class="chapter-kicker">第 3 章 · 模型状态分片</span>

Fully Sharded Data Parallel（FSDP，全分片数据并行）的核心是：**模型状态分片保存，计算前聚合当前单元的参数，反向后归约并分片梯度，各卡更新自己负责的参数。**

本篇作为第 3 章的复习入口，先建立显存与通信账本，再整理工程取舍和面试问答。具体实现见 [3.1–3.5](#reading)。

</div>

## 01 · 分片对象与计算方式 { #basics }

普通 Distributed Data Parallel（DDP，分布式数据并行）让各卡处理不同的数据，但每卡都保存完整的参数、梯度和优化器状态。FSDP 沿数据并行组切分这三类状态，减少每卡的常驻显存。

ZeRO（Zero Redundancy Optimizer）按分片范围分为三个阶段。FSDP 的完整分片配置与 ZeRO-3 对应，但不同框架的调度与 buffer 实现可以不同。

| 方案 | 参数 | 梯度 | 优化器状态 |
| --- | --- | --- | --- |
| DDP | 完整 | 完整 | 完整 |
| ZeRO-1 | 完整 | 完整 | 分片 |
| ZeRO-2 | 完整 | 分片 | 分片 |
| ZeRO-3 / 完整分片 FSDP | 分片 | 分片 | 分片 |

表中描述的是模型状态的分片目标；计算期间仍会临时生成完整参数、局部完整梯度等对象。**激活不属于这三类状态，FSDP 不会自动把激活显存也降到原来的 $1/N$。**

这里 $N$ 是参数分片组的卡数。在未叠加张量并行时，各卡仍用完整的当前层权重计算各自的数据；Tensor Parallel（TP，张量并行）则切分层内的矩阵计算。两者可以组合。

## 02 · 参数与梯度的生命周期 { #lifecycle }

模型通常按 Transformer block 等粒度划成多个 **FSDP 单元**：同一单元的参数一起聚合、计算和释放。以下采用完整分片、前向后释放完整参数的配置，即 PyTorch FSDP2 的 `reshard_after_forward=True`。

| 时刻 | 操作 | 本卡留下什么 |
| --- | --- | --- |
| 单元前向前 | AllGather：聚合各卡参数分片 | 当前单元的完整参数 |
| 单元前向后 | 释放临时完整参数 | 常驻参数分片，以及反向所需的激活 |
| 单元反向前 | 再次 AllGather 参数 | 当前单元的完整参数 |
| 单元反向后 | ReduceScatter：汇总各卡梯度并分片；释放完整参数 | 归约后的梯度分片、参数分片 |
| 优化器更新 | 用本卡梯度和优化器状态更新本卡参数 | 更新后的参数分片 |

执行顺序是**所有单元依次前向，再按相反顺序反向**。因此，前向释放过的参数要在反向前重新聚合。更新后也不必立即恢复全模型参数，下一次计算前再聚合即可。

这形成每轮前向、反向的基本通信：**两次参数 AllGather，加一次梯度 ReduceScatter。** 若前向后保留完整参数，则可以省去反向前的 AllGather，但完整参数的驻留时间更长。实际默认值还受单元位置影响，例如 PyTorch FSDP2 的 `reshard_after_forward=None` 对根单元和非根单元采用不同策略。[PyTorch API](https://docs.pytorch.org/docs/stable/distributed.fsdp.fully_shard.html)

## 03 · 显存与通信账本 { #accounting }

### 显存：常驻状态与运行峰值

设模型有 $P$ 个参数；每个参数对应的常驻参数、梯度、优化器状态分别占 $b_w$、$b_g$、$b_o$ 字节，其中优化器状态口径包含单独保存的主权重（如果存在）。理想均匀分片下：

$$
M_{\text{state}} \approx \frac{P(b_w+b_g+b_o)}{N}
$$

例如，FP32 参数与梯度、两个 FP32 Adam 动量，不另存主权重，账本为 $16P/N$；若另有 BF16 参数、FP32 梯度、FP32 主权重和两个 FP32 动量，则为 $18P/N$。**先列出实际保存的对象，再选择字节数，不能把某个常数当成 FSDP 的固定开销。**

运行峰值还包含激活、临时完整参数与梯度、通信和算子工作区。预取下一单元会让多个单元的参数同时驻留，因此峰值也不只取决于最大的一个单元。显存分析还要区分张量实际占用与内存分配器保留的空间。

### 通信：两次参数聚合与一次梯度归约

统一统计**每卡发送字节数**，取理想 ring 等价通信量，令 $a=(N-1)/N$。设参数聚合时每元素占 $c_p$ 字节，梯度归约时每元素占 $c_g$ 字节；它们可以与常驻存储精度不同。

对一次前向、反向，假设每个参数前向和反向各聚合一次、梯度归约一次，不含额外重计算通信：

| 方案 | 通信组成 | 每卡发送量 |
| --- | --- | --- |
| DDP | 梯度 AllReduce | $2aPc_g$ |
| FSDP，前向后释放完整参数 | 参数 AllGather × 2 + 梯度 ReduceScatter | $aP(2c_p+c_g)$ |
| FSDP，前向后保留完整参数 | 参数 AllGather × 1 + 梯度 ReduceScatter | $aP(c_p+c_g)$ |

同精度通信时，第二行是 DDP 的 **1.5 倍**；若参数用 BF16（$c_p=2$）、梯度用 FP32（$c_g=4$），前两行都是 $8aP$ 字节。例如 $P=10^9$、$N=8$ 时，两者均为每卡发送 7 GB。

这只是字节量比较。FSDP 的参数通信会阻塞尚未拿到权重的计算，DDP 的梯度通信通常更容易与反向重叠，所以**通信量相同也不代表耗时相同**。多个 micro-batch 累积成一个优化器 step 时，还要根据实际同步和参数保留策略重新计数。

## 04 · 性能优化的主要取舍 { #tradeoffs }

FSDP 调优需要同时观察峰值显存和关键路径上未被计算覆盖的通信时间。

| 调整 | 主要收益 | 代价或限制 |
| --- | --- | --- |
| 缩小 FSDP 单元 | 降低一次聚合的完整参数量 | 通信次数增多，启动开销更明显 |
| 增大 FSDP 单元 | 合并小通信，提高带宽利用率 | 临时参数更大，可重叠的调度边界更少 |
| 提前预取下一单元参数 | 用当前计算覆盖下一次 AllGather | 增加同时驻留的参数，预取过晚仍会等待 |
| 前向后保留完整参数 | 省去反向前的参数 AllGather | 完整参数驻留到反向，削弱显存收益 |
| 激活重计算 | 减少保存的激活 | 增加计算；额外通信取决于重计算与分片边界 |
| CPU offload | 将部分模型状态移到 CPU | 增加主机与设备传输，以及 CPU 更新成本 |

跨节点时还可采用 **Hybrid Sharded Data Parallel（HSDP，混合分片数据并行）**：组内分片、组间复制。设每个分片组有 $S$ 张卡，共 $R$ 个副本，则总卡数为 $R S$，模型状态按 $1/S$ 分片，而非 $1/(R S)$。

典型布局是在节点内做参数 AllGather 和梯度 ReduceScatter，再让跨节点的对应 rank 对梯度分片做 AllReduce。例如两节点、每节点 4 卡，节点内分片使每卡常驻状态约为完整状态的 $1/4$；8 卡全分片则约为 $1/8$。HSDP 用更多显存换取较少的跨节点参数通信，效果取决于进程组是否匹配实际拓扑。

## 05 · 常见面试问答 { #interview }

### 1. FSDP 与 ZeRO-3、TP 分别是什么关系？

完整分片 FSDP 实现了与 ZeRO-3 对应的模型状态分片范围；它们不保证使用相同的 buffer 和调度。FSDP 主要切分状态存储，TP 切分层内计算。FSDP 各卡通常处理不同数据，TP 组内各卡协作完成同一层的计算。

### 2. 为什么梯度用 ReduceScatter，而不是 AllReduce？

本卡只更新自己负责的参数分片，因此只需要对应的全局归约梯度。ReduceScatter 正好返回这部分；AllReduce 还会让每卡得到不负责更新的梯度。下一次参数 AllGather 会收集各卡更新后的权重。

### 3. 为什么反向还要再聚合一次参数？

前向后释放了完整参数，而反向计算通常仍需要权重，例如线性层的输入梯度 $dX=dY W^T$。保留完整参数可以省通信，但要付出更长时间的显存占用。

### 4. 为什么用了 FSDP 还是会 OOM？

先区分发生阶段：初始化时可能还没完成分片；运行时可能是激活、过大的 FSDP 单元或过多预取；保存时可能在单卡聚合了完整 checkpoint。$1/N$ 只描述理想常驻模型状态，不是总显存保证。应结合显存快照检查实际存活的张量。

### 5. FSDP 通信量一定比 DDP 多 50% 吗？

只有在参数与梯度通信精度相同、前向后释放完整参数，并且每轮按两次 AllGather、一次 ReduceScatter 计数时成立。混合精度、梯度累积、参数保留和重计算都会改变比较条件；回答时应先说明口径。

### 6. 单元怎么划分？只包住整个模型可以吗？

可以，但一个单元会一次聚合其全部参数，临时完整参数很大，也难以按层重叠通信。Transformer block 常作为起点：先满足显存，再根据通信启动开销和计算间隙调整粒度。单元并非越小越好。

### 7. 开了异步通信，为什么 GPU 仍然等待？

异步提交只表示主机可以继续执行，不代表通信已完成。当前层必须等自己的参数就绪；前一层计算太短、预取太晚、网络拥塞或资源竞争，都会让通信暴露在关键路径上。要在 profiler 中看等待位置与重叠区间，不能只看开关。

### 8. 梯度累积能省掉全部通信吗？

不能。跳过中间 micro-batch 的梯度同步可以减少 ReduceScatter，但参数若已释放，下次计算仍需 AllGather。在 PyTorch FSDP2 中，`set_requires_gradient_sync(False)` 会推迟梯度归约，期间保留未分片梯度，可能明显增加显存；参数是否保留是另一项策略。

### 9. 混合精度下，参数、梯度和优化器必须同一种精度吗？

不必。常驻参数可以是 FP32，聚合后的计算参数是 BF16，梯度用 FP32 归约，优化器状态也保持 FP32。要分别核对存储、计算、通信三种精度，不能只凭“开启 BF16”推算显存与流量。[PyTorch 混合精度示例](https://docs.pytorch.org/tutorials/intermediate/FSDP_tutorial.html#mixed-precision)

### 10. PyTorch FSDP1 与 FSDP2 的关键差别是什么？

FSDP1 主要通过包装模块、展平参数管理分片；FSDP2 使用 `fully_shard`，按原参数组织 DTensor 分片，保留参数名和形状信息，更便于与其他并行方式组合。二者 API 不应混用；FSDP2 应先完成分片，再构造优化器。[PyTorch FSDP2 教程](https://docs.pytorch.org/tutorials/intermediate/FSDP_tutorial.html)

### 11. 参数分片后，梯度裁剪和 checkpoint 要注意什么？

全局梯度范数需要汇总各分片，不能只对本卡分片求范数就当作全局值；应使用支持当前分布式张量布局的裁剪接口。checkpoint 要保存所有分片，不能只保存 rank 0 的局部分片。分布式 checkpoint 可避免单卡聚合完整状态；恢复训练还需优化器、调度器和随机数等状态。

### 12. DDP、全分片 FSDP、HSDP 怎么选？

模型状态放得下时，DDP 往往更简单，也更容易隐藏梯度通信；状态放不下时考虑分片。如果跨节点参数通信成为瓶颈，且节点内分片后显存足够，可考虑 HSDP。若主要是激活过大，则还需要激活重计算或其他针对激活的并行方式。最终比较相同训练目标下的吞吐、峰值显存和扩展效率。
