# 把它们拼起来：多维组合并行与选型

<div class="notebook-hero" markdown>

<span class="chapter-kicker">第 8 章 · 多维组合并行</span>

真实的大模型训练从来不是单一并行，而是 DP × FSDP × TP × PP × CP × EP 的**组合**。一个多维 DeviceMesh 描述 GPU 布局，一套放置原则决定谁放最内、谁放最外。这是全手册的收束。

**本章关键词：** 🗺️ DeviceMesh / parallel_state · 🎯 TP 最内 · PP 最外 · 🌳 选型决策树 · ⚙️ AC / fp8 / overlap

</div>


## 01 · 真实训练 = 组合并行 { #combine }

前面六章每一种并行都解决一个特定问题，但单独用都不够：DP 不省显存、TP 不能跨机、PP 有气泡……所以实际训练把它们**叠起来用**，叫 3D / 4D / 5D 并行。比如一个经典配置：

- 机内 8 卡做 **TP**（吃 NVLink 带宽）
- 若干机做 **PP**（跨节点，通信稀疏）
- 剩下的卡做 **FSDP/DP**（最外层，梯度可重叠）
- 长序列再叠 **CP**，MoE 再叠 **EP**

关键问题变成：**这成百上千张卡，谁和谁组成一个 TP 组、谁和谁组成 PP 组？**


## 02 · DeviceMesh：用多维网格描述 GPU 布局 { #mesh }

Megatron 在 `parallel_state` 里用一个「多维网格」给每张卡分配一组坐标 $(\text{tp\_rank}, \text{dp\_rank}, \text{pp\_rank}, ...)$。以 16 卡、$\text{tp}=2,\text{dp}=4,\text{pp}=2$ 为例，全局 rank 由各维坐标和 **stride** 算出：

$$ \text{global\_rank} = \text{tp\_rank} + \text{dp\_rank}\times 2 + \text{pp\_rank}\times 8 $$


![16 卡的 nD rank 布局：TP 最内、DP 中间、PP 最外](assets/07-nd-figure-01.svg)

*nD 布局的核心：每张卡一组坐标，stride 小的维（TP）相邻、走 NVLink；stride 大的维（PP）跨节点。*



## 03 · 放置原则：谁放最内、谁放最外 { #placement }

| 维度 | 放哪层 | 为什么 |
| --- | --- | --- |
| **TP / EP** | 最内层（NVLink） | 每层都通信、在关键路径、不可重叠 → 必须高带宽 |
| **CP** | 中间层 | 注意力的 KV 通信较密，Megatron 中紧贴 TP 摆放 |
| **DP / FSDP** | 外层 | 每 step 一次、可与反向重叠 → 容忍较低带宽 |
| **PP** | 最外层（跨节点） | 只在 stage 边界传一次激活，通信量最小 |

Megatron 把这套顺序固化成一个字符串 `order='tp-cp-ep-dp-pp'`（最左 = stride 最小 = 最内层）：


**Megatron-LM · core/parallel_state.py:561（initialize_model_parallel 默认 order）**


```python
def initialize_model_parallel(..., order="tp-cp-ep-dp-pp"):
    data_parallel_size = world_size // (tp * pp * cp)   # dp 由 world_size 反推
    decoder_rank_generator = RankGenerator(
        tp=tensor_model_parallel_size, ep=1, dp=data_parallel_size,
        pp=pipeline_model_parallel_size, cp=context_parallel_size, order=order, ...)
```

`RankGenerator` 按 `order` 从右到左依次展开各维（最右 `pp` 步长最大、最左 `tp` 步长最小），为 TP / CP / EP / DP / PP 各生成对应的进程子组。于是**放置原则不是靠手工排卡，而是由这一个字符串决定**：改 `order` 即改物理布局，通信最密的 TP 永远落在 stride 最小、物理最近的卡上。

## 05 · 通用工程调优 { #eng }

- **激活重计算（activation checkpointing）**：前向不存中间激活，反向时重算——用算力换显存。可选择性只重算最贵的几层。
- **混合精度 bf16 / fp8**：计算用低精度、归约用 fp32（见第 3 章的 `MixedPrecisionPolicy`）；fp8 进一步压算力与带宽。
- **通信-计算重叠**：贯穿全书的命脉——DP 反向边算边 all-reduce、FSDP 预取参数、PP 异步 p2p、EP 用 shared expert 盖住 all-to-all。
- **profiling**：用 torch profiler / nsys 定位是通信瓶颈、气泡还是 OOM，再针对性调维度配比。


## 06 · 全手册收束：一张账本，一组原语 { #summary }

回到第 1 章的那张地图——全书其实只讲了一件事：**把显存账本里的不同项切开，用合适的通信原语把结果对齐**。

| 模块 | 切账本里的 | 主原语 | 放置 |
| --- | --- | --- | --- |
| DP | 数据（状态冗余） | all-reduce | 外 |
| FSDP | 参数+梯度+优化器状态 | all-gather + reduce-scatter | 外 |
| TP+SP | 层内参数与计算 / 激活 | all-reduce / AG+RS | 最内 |
| PP | 层（深度） | send/recv | 最外 |
| CP | 序列维激活 | ring p2p / all-to-all | 中 |
| EP | 专家（MoE） | all-to-all | 内 |
